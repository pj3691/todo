# GitStatus 桌面版（Electron 桌宠）实现说明

> 适用版本：`desktop/package.json` 0.1.0（Electron 33.x，electron-builder 25.x）
> 说明对象：`desktop/` 下的 Windows 桌宠桌面端。`desktop/README.md` 是早期版本的使用说明，其中"覆盖整个虚拟桌面的透明覆盖层"的描述已过时，以本文档为准。

---

## 1. 总体定位

桌面版不是一个独立应用，而是**把已有的网页桌宠装进一个桌面窗口**：

- UI、样式、提醒逻辑全部复用后端页面 `src/pages/desktop-pet.html` + `assets/js/pet-widget.js` + `assets/css/pet-widget.css`。
- 数据、登录、提醒、角色素材全部走已有 HTTP 接口（`/gitstatus/api/todo-widget/*`），桌面端不直连数据库。
- Electron 只负责三件事：**窗口与层级**、**鼠标命中与点击穿透**、**系统集成（托盘、默认浏览器、显示器）**。

```
┌───────────────────────────────┐
│ Electron 主进程 main.js        │
│  · 窗口 create/hide/show       │
│  · 命中矩形 → 鼠标穿透切换      │
│  · 托盘 / 显示器 / 外链        │
└──────────────▲────────────────┘
               │ preload.js（contextBridge + ipcRenderer）
┌──────────────┴────────────────┐
│ 渲染进程：desktop-pet.html     │
│  · pet-widget.js（拖拽/气泡/提醒）│
│  · 命中矩形采集与上报            │
└──────────────▲────────────────┘
               │ fetch（同源）
┌──────────────┴────────────────┐
│ 后端 http://localhost:30012    │
│  · /todo-widget/summary 等     │
└───────────────────────────────┘
```

### 目录与职责

| 文件 | 职责 |
| --- | --- |
| `desktop/main.js` | 主进程全部逻辑：配置读取、窗口创建、命中/穿透、拖拽辅助、托盘、显示器、隐藏/显示、登录窗/待办窗、离线页、单实例 |
| `desktop/preload.js` | 用 `contextBridge` 暴露 `window.desktopApi`，渲染进程不接触 Node |
| `desktop/offline.html` | 后端未启动时的重连页（与桌宠同窗口加载） |
| `desktop/config.json` | 后端地址配置（`serverUrl`） |
| `desktop/tray.png` | 托盘图标 |
| `src/pages/desktop-pet.html` | 桌面版渲染页：注入 `GITSTATUS_PET_CONFIG`、采集命中矩形、拦截链接、处理隐藏/显示事件 |
| `src/pages/desktop-login.html` + `assets/js/desktop-login.js` | 桌面版登录窗页面，登录成功回调主进程 |
| `src/pages/assets/js/pet-widget.js` | 通用桌宠挂件：拖拽、气泡、提醒轮询、设置面板；通过 `desktop` / `desktopStage` 开关进入桌面模式 |

## 2. 启动与配置

### 2.1 后端地址解析

`readServerUrl()`（main.js 顶部）按优先级取值：

1. 环境变量 `GITSTATUS_URL`；
2. `desktop/config.json` 的 `serverUrl`；
3. 默认 `http://localhost:30012`。

返回值会去掉结尾斜杠，`petUrl = ${serverUrl}/pages/desktop-pet.html?v=${Date.now()}`——时间戳是为了避免 Electron 缓存住旧页面（历史上出现过改完 `pet-widget.js` 不生效的问题）。

### 2.2 启动与单实例

- 入口 `desktop/main.js`，`npm --prefix desktop start`（或仓库根 `npm run desktop`）。
- `app.requestSingleInstanceLock()`：拿不到锁直接退出；第二个实例触发 `second-instance` → `showPet()`。
- `app.setAppUserModelId("com.gitstatus.pet")`（与打包 `appId` 一致，保证托盘/通知归属正确）。
- `app.whenReady()` 后依次：`registerIpc()` → `createPetWindow()` → `createTray()` → 监听显示器变化。

### 2.3 全局网络策略

`app.on("web-contents-created")` 对所有窗口统一设置（详见 8.4）：

- `setWindowOpenHandler` → 一律 `deny`，改走 `shell.openExternal`。避免 `window.open` 生成空白 Electron 窗口（项目管理页打开项目地址时踩过）。
- `will-navigate` → 非同源跳转一律阻止并交给系统浏览器；`file:`、`devtools:` 和 `serverUrl` 同源放行。

## 3. 窗口模型

### 3.1 桌宠舞台窗 `petWin`（核心）

`createPetWindow()` 关键参数：

| 项 | 值 | 原因 |
| --- | --- | --- |
| 尺寸 | 初始 420×720，加载后按内容包围盒自适应 | 局部舞台：窗口始终刚好包住“桌宠 + 当前气泡/面板”（见 §4.7） |
| 窗口样式 | `frame:false`、`transparent:true`、`backgroundColor:#00000000`、`hasShadow:false`、`skipTaskbar:true` | 无边框透明台面，不占任务栏 |
| 层级 | `alwaysOnTop:true` + `setAlwaysOnTop(true,"screen-saver")` | 压住普通窗口 |
| `show` | `false`，`ready-to-show` 后 `showInactive()` | 不抢焦点；另有 2 秒兜底 `showInactive`（加载失败时 `ready-to-show` 可能不触发） |
| `webPreferences` | `preload`、`contextIsolation:true`、`sandbox:true`、`nodeIntegration:false`、`backgroundThrottling:false` | 安全隔离；关闭后台节流保证提醒轮询和动画 |
| 初始位置 | 目标显示器 `workArea` 右下角，并用 `min/max` 钳制在屏幕内 | 位置来自 `display-state.json`，无记录时才用默认 |

其他行为：

- `close` 事件（Alt+F4 / 系统关闭）：除非 `allowQuit`，否则 `preventDefault()` → `hidePet()`，即收进托盘。
- `did-fail-load`（主框架且 URL 属于后端）→ 同窗口加载 `offline.html?server=...`。
- `closed` → `petWin = null`。

### 3.2 登录窗 `loginWin`

- 460×620（受屏幕尺寸限制），居中于当前显示器，带 `preload`。
- 加载 `desktop-login.html`；关闭时 `restorePetOverlay()`。
- 登录成功由页面调用 `desktopApi.loginDone()` 通知主进程（见 §9）。

### 3.3 待办窗 `todoWin`

- 1280×860（受屏幕限制），居中，`show:false` 等 `ready-to-show`。
- **不带 preload**：它只是普通网页窗口，因此项目页/待办页里的 `window.open` 完全依赖 §2.3 的全局拦截。
- 支持 `?add=1` 直达新建待办弹窗（`openTodoAddWindow`）；已存在窗口时复用并按需重新加载。
- 关闭时 `restorePetOverlay()`。

### 3.4 离线页

后端未启动时，`did-fail-load` 会把桌宠窗口导航到 `desktop/offline.html`：

- 卡片提示启动后端 + 显示当前 `serverUrl`；
- "重新连接"调用 `desktopApi.retry()` → 主进程重新 `loadURL(petUrl)`；
- 透明区域同样通过 `setInteractive()` 保持点击穿透，只有卡片接收鼠标。

## 4. 点击穿透：局部舞台 + 命中矩形

这是桌面版最关键、也最容易出问题的一环。

### 4.1 页面侧：采集与上报

`desktop-pet.html` 内联脚本负责：

1. **命中矩形采集** `collectHitRegions()`：按“部件组”分别合并为一个包围盒，避免逐元素外扩造成互相错位——
   - 桌宠组：`.pet-widget / .pet-avatar / .pet-menu-btn / .pet-add-btn / .pet-todo-btn`；
   - 小气泡组：`.pet-mini`；
   - 大面板组：`.pet-bubble`；
   过滤掉 `display:none / visibility:hidden / opacity<=0.01 / 尺寸为 0` 的元素，四边各外扩 1px 并裁剪到窗口尺寸，通常输出 1~3 个刚好包住对应部件的矩形。
2. **上报节流** `reportHitRegions()`：
   - 拖动中（`.pet-widget.is-dragging`）直接跳过，拖动由主进程/窗口移动负责；
   - 用 `JSON.stringify(regions)` 做签名去重，不变就不发；
   - 通过 `requestAnimationFrame` 合帧，且每 150ms 兜底一次；
   - `resize`、`pointermove`、`pointerup`、`MutationObserver`（`class/style/aria-hidden`）都会触发重新采集。
3. 通过 `desktopApi.setHitRegions(regions)` 发给主进程。

### 4.2 主进程侧：`applyPetShape()`

- 逐个矩形做**取整 + 边界裁剪 + 去重**，结果缓存到 `petHitRegions`；
- 用 `lastPetShapeKey` 比对，矩形一致则直接返回；
- `petShapeSupported` 当前恒为 `false`（`createPetWindow` 里显式置 false），因此不会调用 `petWin.setShape(rects)`——这是刻意的：Windows 会给原生窗口区域额外画一圈矩形阴影，视觉上很脏；
- 于是命中判断改由下面的 `petHoverGuard` 按矩形切换鼠标穿透。

### 4.3 悬停守卫 `petHoverGuard`（25ms）

`startPetHoverGuard()` 每 25ms：

1. 窗口已销毁或已隐藏 → 清空 `petHoverInside` 并返回；
2. `petShapeSupported` 为真、或正在拖动（`petDragOffset/petDragActive`）→ 跳过（拖动期间不切换穿透，避免闪烁）；
3. 读 `screen.getCursorScreenPoint()`，换算成窗口内坐标，判断是否落在任一命中矩形；
4. 与上次结果不同才调用 `petWin.setIgnoreMouseEvents(!inside, { forward: true })`。

`forward: true` 保证穿透状态下鼠标事件仍会转发给页面（用于 `mousemove` 采集）。

### 4.4 其他窗口打开时的处理

- `suspendPetOverlay()`：打开待办/登录窗前调用，清掉残留拖动状态；
- `restorePetOverlay()`：窗口关闭后调用，重置 `petHoverInside` 让守卫重新判定（否则缓存的 true 会让桌宠点不动）。

### 4.5 `pet:interactive` 的定位

页面 `mousemove` 里也会调 `setInteractive()`，但主进程处理函数中有 `if (!petShapeSupported) return;`——即**当前架构下命中切换完全由主进程守卫负责**，页面这条通道只服务于 `setShape` 方案（保留兼容）。`offline.html` 仍在使用它。

### 4.6 调试模式（显示舞台边框）

桌宠设置面板（气泡 → 设置 → 桌面桌宠）里有一个「调试模式」开关，用于定位窗口与命中区域问题：

- 开关状态存 localStorage：`gitstatus_pet_debug_frame_v1`；
- 切换时 `pet-widget.js` 派发自定义事件 `gitstatus-pet-debug-frame`，由 `desktop-pet.html` 负责绘制（页面初始加载时也会读一次 localStorage）；
- 绘制内容（`pointer-events:none`，不影响点击与命中）：
  - **红色虚线**：舞台窗口边框，左上角标签显示 `舞台 420×720 · 桌宠 x,y`；
  - **细红线**：窗口水平/垂直中线，便于对照锚点方向；
  - **蓝色框**：`collectHitRegions()` 采集到的命中矩形（含 12px 外扩，与主进程判断一致）；
  - **绿色框**：`.pet-widget` 的实际包围盒。
- 每 150ms 刷新一次，矩形签名不变时不重建节点；关闭开关会立即移除图层并停止定时器。

### 4.7 窗口固定 420×720（自适应已回滚）

当前窗口尺寸固定为 `PET_STAGE_WIDTH × PET_STAGE_HEIGHT`（420×720），页面 `reportContentBox()` / `reportContentBoxNow()` 为空实现，不再上报内容尺寸，主进程也不会再 `setBounds`。

曾尝试过两版自适应（视口测量版、纯常量几何版），都因“窗口移动 ↔ 页面坐标”双向异步难以稳定而回滚：实测会出现窗口尺寸与内容不一致、桌宠被推出窗口、气泡被裁剪。若后续重启该能力，建议：以主进程为唯一坐标真源、面板尺寸全部用常量、不读布局。

固定舞台下的行为：

- 气泡：宽度 322（设置 384），高度随内容，`max-height: min(560px, 100vh - 24px)`，四向避让并夹在工作区内；
- 小气泡：`.pet-mini` 相对桌宠定位（CSS `right/bottom`），`positionMini()` 只处理上下翻转与左右越界平移；
- 命中区域仍按“部件组”合并上报，与窗口大小无关。

以下为曾实现的自适应细节，保留供参考：

配套改动：

- 气泡宽度以**屏幕工作区**为基准（`screenViewport()`），不再受 `innerWidth` 限制，否则窗口收缩后气泡会被压成一条缝，形成死锁。
- `is-right`（气泡左右展开/镜像方向）改为按**显示器中线**判断，而不是窗口中线。
- 拖动期间不调整窗口（`petDragOffset/petDragActive` 直接跳过）；切屏、显示器变化时 `resizePetWindow()` 会把窗口放回 420×720 并清空 `lastAppliedContentBox`，页面随后重新上报收缩。

### 4.8 形变期间先量尺寸再展示（随自适应一起停用）

当前不启用：气泡打开即显示，不进入 `is-stage-adjusting`。启动自适应时，“先量尺寸→调窗→完成回调后再展示”本用于避免气泡先在小窗口渲染一帧再被撑开。

1. `showBubble()` / `showMini()` 先 `beginStageAdjust()`：给 `body` 加 `is-stage-adjusting`，气泡加 `is-measuring`（`opacity:0`、不接收点击），并在该状态下禁用 `.pet-bubble` / `.pet-mini` 的 transition；
2. 立即 `reportContentBoxNow()`（跳过节流）把含隐藏气泡的包围盒发给主进程；
3. 主进程 `setBounds(..., false)` 一步调到位，回发 `pet:stage-bounds`；页面 `applyStageBounds()` 后调用 `finishStageAdjust()`，移除 `is-stage-adjusting` / `is-measuring`，此时才加 `is-open` 让气泡淡入；
4. 兜底定时器（气泡 200ms、小气泡 160ms）防止窗口无需变化时气泡一直不出现；打开新气泡前关闭旧气泡/小气泡时传 `{ silent: true }`，避免“先收缩一次再扩展”的双跳。

## 5. 拖动实现

拖动逻辑在 `pet-widget.js` 的 `onPointerDown / onPointerMove / applyDesktopDrag / onPointerUp`。

### 5.1 触发与状态

`pointerdown`（仅左键、仅桌宠本体）时记录：

- 桌宠矩形、指针在桌宠内的偏移；
- 起始光标屏幕坐标（优先 `desktopApi.getCursorPoint()` 同步 IPC，拿不到才用 `event.screenX`）；
- 桌宠起始屏幕坐标（`window.screenX + rect.left`）；
- 舞台窗口起始屏幕坐标（`window.screenX / screenY`）；
- 当前显示器 `workArea`（`screen.availLeft/availTop/availWidth/availHeight`）。

`windowDrag` 为真需要三个条件：`desktopStage` 模式 + `setDesktopDragging` + `getCursorPoint` 都存在。此时**按下瞬间**就先调用 `setDesktopDragging(true)`，让主进程停掉 hover guard，避免第一帧穿透切换造成方向性闪烁。

### 5.2 每帧跟随（rAF）

位移超过 `dragThreshold=4` 后进入拖动，启动 `requestAnimationFrame` 循环：

1. `getCursorPoint()` 取**主进程读到的真实光标**——窗口移动会让 pointer 事件的 `screenX/Y` 回跳，用事件坐标会抖；
2. 用光标位移量算出目标桌宠屏幕位置，并按 `workArea` 钳制；
3. 换算成舞台内局部坐标；**只有当局部坐标超出舞台留白时，才调用 `window.moveTo()` 移动窗口**（窗口尽量不动，减少 DWM 合成开销）；
4. 移动后用**真实**的 `window.screenX/screenY` 反算局部 `left/top` 并写入样式——即使窗口移动晚一帧生效，桌宠仍贴在光标下；
5. 按桌宠中心相对屏幕中线切换 `is-right`（小气泡朝向）与 `is-flipped`（镜像）。

### 5.3 松手

`pointerup`：

- 取消 rAF、移除监听、清理 `is-dragging`；
- 调用 `setDesktopDragging(false)`：主进程据此更新 `petDisplayId`、`saveDisplayState()`、刷新托盘、重新置顶；
- 未发生位移视为点击 → `toggleMini()`；
- 拖动期间被压下的提醒队列延迟 300ms 后继续播放。

### 5.4 主进程保留的拖拽 IPC

`main.js` 中仍有 `pet:window-drag-start / tick / finish-layout / complete / end` 与 `movePetStage()` 等，属于**上一版"拖动时把 420×720 舞台收缩成桌宠大小"的方案**：

- 收缩后窗口小、移动便宜；松手时用 `finish-layout` 在同一帧恢复舞台尺寸与锚点；
- 当前页面已改用 §5.2 的"窗口尽量不动 + 内嵌移动"方式，这些通道仅作兼容保留（`pet:window-drag-end` 注释也写明"兼容旧页面"）。

## 6. 置顶、显示与隐藏

### 6.1 置顶守卫

- `keepPetOnTop()`：`setAlwaysOnTop(true, "screen-saver")`；
- `focus` 立即补、`blur` 延迟 80ms 补、`show`/`restore` 延迟 30ms 补、`always-on-top-changed` 被改掉也立刻补回；
- `startPetTopGuard()` 每 5 秒只补标记，**不做 `moveTop`**——后者会干扰浏览器标签页拖拽。

### 6.2 隐藏（收进托盘，销毁窗口）

当前采用 **close 方案**：隐藏时直接销毁渲染进程，显示时重建。

`hidePet()`：

1. 向页面发 `pet:event = before-hide`，页面用 `showMiniNotice("goodbye")` 播报再见气泡，1.1 秒后调 `hideNow()`；
2. 主进程 1600ms 兜底计时，超时直接 `finishHide()`；
3. `finishHide()`：发 `hidden` → `petWin.destroy()` → `petWin = null`；`closed` 里清空 `petHitRegions` / `petHoverInside` / 拖动状态，并刷新托盘菜单。

`window-all-closed` 已改为不退出（托盘常驻），真正的退出走托盘菜单/设置里的“退出桌宠”。

代价（与 `hide()` 方案相比）：

- 再次显示要重新 `loadURL`，会经历一次页面加载（本地后端约 200~500ms，窗口 `show:false` 直到 `ready-to-show`，期间不闪烁但出现得稍慢）；
- 隐藏期间页面轮询停止（不再拉摘要/本地提醒检查），显示后重新开始；
- `pet-widget` 的内存状态（气泡类型、提醒队列、未读标记）重建后重置，登录态不受影响（localStorage）。

### 6.3 显示

`showPet()`：

- **窗口已被销毁**：直接 `createPetWindow()` 重建（重读显示器/位置状态、重置命中与拖动状态），托盘菜单同步为“隐藏桌宠”；
- **窗口仍在**（例如隐藏流程还没走完又点了显示）：`setOpacity(1)`、`showInactive()`、`invalidate()` 强制重绘、按 `petShapeSupported / overlaySuspended` 恢复鼠标策略、重新置顶（30ms 后再补一次），然后发 `after-show`，并在 80ms 后校正穿透、320ms 后再补发一次 `after-show`。

页面侧收到 `after-show`（或监听到 `visibilitychange` 变可见）时：移除 `pet-hidden`、恢复 `hitPaused`、清签名并重报命中（rAF + 60/80ms 直发）、播报 welcome 气泡。

> 注意：隐藏状态下 `petHoverInside`、`petDragActive`、`petDragOffset` 都会被重置，否则守卫会沿用旧判定，导致"显示出来点不动"。

### 6.4 托盘

`createTray()` + `updateTrayMenu()`：

- 单击托盘图标：显示 ↔ 隐藏；
- 右键菜单：显示/隐藏桌宠、显示器子菜单（多屏时，radio 选择）、打开待办、重启桌宠、退出桌宠；
- 「重启桌宠」`restartDesktop()`：portable 版用 `PORTABLE_EXECUTABLE_FILE` 作为 `execPath` 重新拉起，其余环境直接 `app.relaunch()`。

## 7. 显示器与位置持久化

- 状态文件：`app.getPath("userData")/display-state.json`，内容 `{ displayId, x, y }`。
- `readDisplayState()` 在创建窗口时读取；`saveDisplayState()` 在窗口移动、拖动结束、显示器变化、切换屏幕时写入。
- 位置约束：创建/重排时都用 `workArea` 做 `Math.max/min` 钳制，副屏被拔掉时 `handleDisplaysChanged()` 回退到主屏。
- `screen` 事件（`display-metrics-changed / display-added / display-removed`）→ `resizePetWindow()` 把舞台放回目标屏右下角并保存。
- 切换显示器：托盘菜单或桌宠设置面板 → `pet:move-display` / `moveToDisplay()` → `movePetToDisplay()` 重置位置并给页面发 `pet:anchor`（页面 `setStageAnchor()` 把桌宠贴回舞台右下角）。
- 反向同步：页面每次保存位置会 `reportPetPosition(桌宠中心屏幕坐标)`，主进程用 `getDisplayNearestPoint()` 更新 `petDisplayId`。

## 8. preload 与 IPC 清单

### 8.1 同步 API

| 方法 | 通道 | 说明 |
| --- | --- | --- |
| `getCursorPoint()` | `pet:cursor`（`sendSync`） | 拖动跟手、计算偏移 |
| `desktopInitialDisplay`（全局变量） | `pet:initial-display`（`sendSync`，仅在 preload 加载时取一次） | 首帧定位用：虚拟桌面范围 + 当前显示器区域 |

### 8.2 异步/单向 API

| 方法 | 通道 | 主进程行为 |
| --- | --- | --- |
| `setInteractive(bool)` | `pet:interactive` | 仅 `petShapeSupported` 时切换穿透 |
| `setHitRegions(regions)` | `pet:hit-regions` | → `applyPetShape()` |
| `setContentBox(box)` | `pet:content-box` | → `applyPetContentBox()`，按内容收缩/扩展窗口并回发 `pet:stage-bounds` |
| `getDisplays()` | `pet:get-displays`（invoke） | 返回当前显示器 + 全部显示器（含 workArea） |
| `moveToDisplay(id)` | `pet:move-display` | `movePetToDisplay()` |
| `reportPetPosition(x,y)` | `pet:position` | 按光标所在显示器更新 `petDisplayId` |
| `moveWindow(x,y,size)` | `pet:move-window` | `movePetStage()`，按光标显示器 workArea 钳制 |
| `setDesktopDragging(bool)` | `pet:desktop-drag-active` | 拖动开始/结束：停/恢复 hover guard，结束时保存状态 |
| `startWindowDrag / windowDragTick / finishWindowDragLayout / completeWindowDrag / endWindowDrag` | `pet:window-drag-*` | 旧"收缩舞台"拖动方案的通道，保留兼容 |
| `openLogin()` | `pet:open-login` | 打开登录窗 |
| `openTodo()` / `openTodoAdd()` | `pet:open-todo` / `pet:open-todo-add` | 打开待办窗（可直达新建） |
| `hidePet()` / `hideNow()` | `pet:hide` / `pet:hide-now` | 播报后隐藏 / 立即隐藏 |
| `openExternal(url)` | `pet:open-external` | 仅 `http/https` 交给 `shell.openExternal` |
| `loginDone()` | `pet:login-done` | 关闭登录窗、重置鼠标状态、重新加载桌宠页 |
| `retry()` | `pet:retry` | 重新 `loadURL(petUrl)` |
| `quit()` | `pet:quit` | `app.quit()` |
| `onPetEvent(cb)` | 监听 `pet:event` | `before-hide / hidden / after-show / display-changed` |
| `onStageAnchor(cb)` | 监听 `pet:anchor` | `{ right, bottom, petSize }` |
| `onStageBounds(cb)` | 监听 `pet:stage-bounds` | `{ x, y, width, height, shiftX, shiftY }`，页面按**实际位移**补偿桌宠局部坐标，不再读 `screenX` |

### 8.3 安全边界

- 渲染进程 `sandbox:true` + `contextIsolation:true` + `nodeIntegration:false`，只能看到 preload 暴露的方法。
- 绝大多数 handler 都校验 `event.sender === petWin.webContents`，防止其他窗口伪造桌宠指令；`pet:get-displays`、`pet:initial-display` 未做 sender 校验（只返回只读的显示器信息）。
- `openExternal` 只放行 `http/https`，其他协议忽略。

### 8.4 全局外链策略

```js
app.on("web-contents-created", (_event, contents) => {
    contents.setWindowOpenHandler(({ url }) => { openExternal(url); return { action: "deny" }; });
    contents.on("will-navigate", (event, url) => { /* 非同源 → preventDefault + openExternal */ });
});
```

## 9. 登录与会话

1. 未登录时页面在 `load` 后 400ms 检查 `localStorage.gitstatus_todo_token`，没有就 `showSummary()` 弹出摘要气泡，引导点"去登录"。
2. 气泡的登录入口走 `GITSTATUS_PET_CONFIG.onLogin` → `desktopApi.openLogin()`。
3. 主进程打开 `loginWin`（460×620）加载 `desktop-login.html`；页面里的 `desktop-login.js` 登录成功后调用 `finishLogin()`：
   - 有 `desktopApi.loginDone` → 交给主进程；
   - 普通浏览器里则跳转 `/pages/todo.html`。
4. 主进程收到 `pet:login-done`：关闭登录窗 → 重置 hover/拖动状态 → `setIgnoreMouseEvents(true)` → 重新 `loadURL(petUrl)`（带新时间戳，确保读到新登录态）。
5. 登录态与网页端共用同一个 localStorage 键，隐藏到托盘再打开不需要重新登录。

## 10. 桌面模式与网页模式的差异

`desktop-pet.html` 在加载 `pet-widget.js` **之前**注入：

```js
window.GITSTATUS_PET_CONFIG = {
    desktop: true,        // 桌面模式：位置交给窗口，拖拽移动窗口
    desktopStage: true,   // 局部舞台模式：桌宠固定在舞台右下角
    initialPosition,      // 虚拟桌面内的当前显示器区域
    onLogin: () => window.desktopApi?.openLogin()
};
```

由此产生的行为差异：

| 行为 | 网页版 | 桌面版 |
| --- | --- | --- |
| 初始位置 | `localStorage` 记录的坐标 | 舞台右下角（`restorePosition()` 在 `desktopStage` 下直接贴边） |
| 拖拽 | 页面内移动元素 + 边缘吸附 | rAF 跟光标，必要时移动窗口（§5） |
| 待办入口 | 跳转 `/pages/todo.html` | `desktopApi.openTodo()` 在应用内窗口打开 |
| 关闭/隐藏 | 移除挂件 | `desktopApi.hidePet()` 收进托盘 |
| 链接点击 | 直接跳转 | `desktop-pet.html` 拦截：todo 页 → 应用内窗口；`data-pet-add` → 直接新建；其他 → 系统浏览器 |
| 待办页内嵌桌宠 | 默认显示 | 默认隐藏，可用账号卡片里的"待办页桌宠"开关打开（`pet-preference.js`，localStorage 键 `gitstatus_pet_todo_visible_v1`） |
| 调试边框 | 无 | 设置面板「调试模式」开关，绘制舞台边框/中线/命中矩形/桌宠矩形（§4.6） |

## 11. 提醒与轮询

桌面版没有额外的后台服务，提醒完全由页面驱动（因此窗口必须关掉后台节流）：

- `pollMs = 25000`：每 25 秒拉一次 `/gitstatus/api/todo-widget/summary`，得到当天摘要与 `nextReminder`；
- `tickMs = 15000`：本地检查间隔提醒、上下班提醒（`workGraceMinutes = 10` 分钟宽限）；
- 摘要气泡 10 秒自动隐藏、提醒气泡 30 秒自动隐藏（`summaryAutoHideMs / reminderAutoHideMs`）；
- 角色素材：`/todo-widget/assets/pet`（按账号保存），大小/镜像等偏好存 localStorage。

## 13. 已知限制与踩坑记录

1. **`setShape` 会带来矩形阴影**：Windows 给原生窗口区域额外绘制一圈阴影，视觉上很脏，因此默认关闭，改用 25ms 光标守卫切换穿透。代价是穿透判断有最多 25ms 延迟。
2. **主进程 16ms 定时器实测只有约 35Hz**：拖动跟手必须由页面 `requestAnimationFrame` 驱动，主进程只做状态与钳制。
3. **透明窗口参与 DWM 合成，每帧移动大窗口会掉帧**：所以采用 420×720 局部舞台，拖动时尽量只移动页面内元素，只在越界时移动窗口。
4. **窗口移动会让 pointer 事件的 `screenX/Y` 回跳**：必须用主进程 `getCursorPoint()` 的真实光标坐标计算。
5. **`window.open` 在 Electron 中默认开空白窗口**：必须全局 `setWindowOpenHandler` → `shell.openExternal`（项目页"打开项目地址"踩过）。
6. **软件渲染下 `backdrop-filter` 极慢**：主进程 `app.disableHardwareAcceleration()`（透明置顶窗在某些显卡上拖影的妥协），因此页面侧全屏模糊要慎用（项目管理弹窗已去掉全屏模糊）。
7. **隐藏后再显示**：现在采用 **close 方案**——隐藏即 `petWin.destroy()`，显示时重建，从根本上避开“渲染进程挂起 → 停在最后一帧 / 命中矩形过期”。重建后页面是全新实例，命中与拖动状态由 `closed` 清空；若走非销毁路径（隐藏流程未完成又点显示），仍依靠 `after-show` 双发 + `visibilitychange` 作为兜底。
8. **拖动状态残留会让守卫永远跳过**：打开待办/登录窗前 `suspendPetOverlay()` 会主动清状态。
9. **目前只在 Windows 验证**：穿透依赖 Windows 上的 `setIgnoreMouseEvents(..., { forward: true })`；`setAlwaysOnTop(level)` 的 level 参数也有平台差异。
10. **桌面版不负责启动后端**：后端未启动时只能看到 `offline.html` 的重连页。
11. **气泡内容异步变高会“歪”到桌宠头上**：气泡位置只在打开时算一次（`placeBubble()`），而摘要/面板内容往往异步渲染，高度变化后不会重排。现在 `pet-widget.js` 用 `ResizeObserver` 监听 `.pet-bubble` 尺寸，变化时经 rAF 重新 `placeBubble()`。

## 14. 排查建议

- **桌宠看不见**：先看托盘菜单是否处于"隐藏桌宠"；再看窗口是否被判断为透明穿透（把光标移到桌宠上，25ms 内应恢复交互）。
- **位置/命中区域对不上**：在桌宠设置面板打开「调试模式」，会画出舞台边框（红虚线）、中线、命中矩形（蓝框）与桌宠实际矩形（绿框），标签上还有舞台尺寸和桌宠坐标，可直接对照主进程的钳制逻辑排查。
- **桌宠点不动**：确认没有残留的 `.is-dragging`，或先打开/关闭一次待办窗触发 `restorePetOverlay()`。
- **显示离线页**：检查 `config.json` 的 `serverUrl` 与后端实际端口（默认 30012）；页面上会回显当前地址。
- **提醒不弹**：确认窗口没被最小化到托盘（隐藏后轮询仍在跑，但气泡不会显示）；`backgroundThrottling` 已关闭，若仍不触发，检查 `/todo-widget/summary` 是否 200。
- **改了 `main.js` 没生效**：桌面端跑的是打包产物时，必须重新 `npm run dist` 并重启。
- 后端侧日志在 `src/output/logs/YYYY-MM-DD.log`，桌面端请求都会记 ACCESS 行，可用于确认页面是否连上后端。
