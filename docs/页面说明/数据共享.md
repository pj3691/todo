# 数据共享页面使用说明

> 页面地址：`/gitstatus/pages/shares.html`
> 作用：把**自己的待办文件夹或收件箱**授权给别的账号，对方在自己的待办清单里就能看到、并按权限协作。
> 通用部分（导航、登录、角色、页面桌宠）见 [通用交互与登录](通用交互与登录.md)；共享数据在待办页的样子见 [待办清单](待办清单.md)。

![数据共享页面](../screenshots/数据共享.png)

---

## 一、这一页解决什么问题

待办数据默认**完全按账号隔离**，别人看不到你的任何任务。想让同事看到某个文件夹，就在这里建一条共享记录 —— 数据库里一条 `todo_shares` 描述的就是「谁（owner）把哪个范围（scope）以什么权限（permission）给了谁（grantee）」。

副标题原文：「把待办文件夹或收件箱的只读 / 增删改权限共享给其他用户」。

要点先记住三条：

1. **共享是只增不减视图的**：被共享方看不到你的其他文件夹，也看不到你没共享的任务。
2. **文件夹共享是连带的**：弹窗里的 hint 原文是「文件夹会连同其子文件夹和其中的任务一起共享」。
3. **数据不会搬家**：任务永远属于创建者，被共享方改的也是所有者那份数据。

## 二、进入门槛

| 条件 | 结果 |
| --- | --- |
| 未登录 | 显示 `登录数据共享` 面板，只有用户名 / 密码 / `登录`；点头像区也会跳到待办页登录 |
| 角色是 `只读` | 页面能打开，但点 `新建共享` 会被挡：toast `只读账号不能创建共享` |
| 角色是 `读写` / `管理员` | 完整功能 |

> 后端把整组共享接口（包括列表查询）都挂在写权限中间件之后，所以只读账号连 `GET /todo-shares` 都会拿到 403。想管理共享，请先升级为 `读写`。

## 三、三个页签与表格

页签区（`aria-label="共享范围"`）：

| 页签 | 含义 | 谁能看到 |
| --- | --- | --- |
| `共享给我的` | 别人授权给我的记录（默认选中） | 所有人 |
| `我共享出去的` | 我作为所有者创建的记录 | 所有人 |
| `全部共享` | 系统内所有共享记录 | **仅管理员**（非管理员该页签是隐藏的，直接请求 `scope=all` 会 403） |

卡片标题随页签切换为 `共享给我的` / `我共享出去的` / `全部共享`，右侧统计是 `共 N 条`；没有数据时表格区显示 `暂无共享记录`，加载中显示 `加载中…`。

表格列固定六列：

| 列 | 内容 |
| --- | --- |
| 数据范围 | 上行是范围名（收件箱显示 `收件箱`，文件夹显示**完整层级路径**），下行是类型标记 `收件箱` / `文件夹`；文件夹已被删除时显示 `文件夹已删除` |
| 所有者 | 数据归属账号的用户名 |
| 被共享给 | 接收方用户名 |
| 权限 | 徽标 `只读` 或 `可编辑` |
| 更新时间 | 后端返回的时间字符串 |
| 操作 | 见下一节 |

列表统一按创建时间倒序；`全部共享` 最多返回 500 条。

## 四、操作列：不是所有人都能改

`操作` 列按「你能不能管这条共享」渲染两种形态：

```
可管理  →  权限下拉（只读 / 可编辑） + 红色按钮 取消共享
不可管理 →  只有一个权限徽标（纯展示）
```

判定规则：**这条共享的所有者是我，或者我是管理员**。也就是说：

- 在 `共享给我的` 页签里，别人共享给你的记录你只能看，不能改权限、也不能"取消"——要收回只能由所有者操作（或管理员代劳）。
- 管理员在 `全部共享` 里可以修改和删除任何人的共享。

| 操作 | 交互 | 提示原文 |
| --- | --- | --- |
| 改权限 | 直接在下拉里换 | 成功 `权限已更新`；失败 `修改权限失败` |
| 取消共享 | 弹确认框，正文 `确定取消「<范围名>」的共享吗？`（收件箱时范围名是 `该共享`） | 成功 `已取消共享`；失败 `取消共享失败` |

取消共享只删这条授权记录，**任务数据本身不受影响**。对方下次刷新就从自己的树里消失了。

## 五、新建共享

工具栏 `新建共享` 打开弹窗（标题 `新建共享`，底部 `取消` / `创建共享`）。

| 字段 | 形态 | 说明 |
| --- | --- | --- |
| 数据范围 | 下拉 | 第一项固定是 `收件箱（N 个任务）`，其后是**你自己的**每个文件夹，显示为 `父级 / 子级（N 个任务）`。这里的 N 只统计未删除的活跃任务 |
| 被共享用户 | 下拉 | 候选是**除你之外所有"已启用"的账号**，按用户名排序；没有候选时显示 `暂无可共享的用户`（通常是系统里只有你一个用户，或对方还在待审核/已禁用） |
| 权限 | 下拉 | `只读：可以查看，不能修改` / `可编辑：可以新增、修改、删除任务` |

校验与结果：

| 情况 | 提示 |
| --- | --- |
| 没选范围或没选人 | `请选择数据范围和被共享用户` |
| 选中的文件夹已不存在 | `文件夹无效` |
| 成功 | `共享已保存` |
| 失败 | `创建共享失败` / `创建失败（HTTP 状态码）` |

几个容易踩的点：

- **重复共享不会报错，也不会产生第二条**：同一个人 + 同一个范围再次提交，会把已有记录的权限**覆盖更新**（HTTP 200 而不是 201）。想从只读升到可编辑，重新建一次即可，不必先删。
- **不能共享给自己**（后端拒绝）。
- **目标账号被禁用时不能共享**；待审核账号不出现在下拉里。
- 下拉里选的是**子文件夹**也可以，但更常见的做法是共享父文件夹 —— 子文件夹自动继承（见下一节）。

## 六、权限到底怎么算

### 6.1 文件夹是「整棵子树」共享

判定某个文件夹对某人的权限时，后端会**从该文件夹沿父链向上找**，命中任意一层祖先的共享即视为有权限，多条命中时**取最高的那个**（`可编辑` 优先于 `只读`）。因此：

- 共享 `工作 / 项目A`，那么 `工作 / 项目A / 迭代1` 也可见；
- 单独再给 `工作 / 项目A / 迭代1` 加一条 `可编辑`，父级是只读也不影响 —— 子级取到更高的那条。

### 6.2 收件箱是独立范围

`收件箱` 指没有归到任何文件夹的任务。共享收件箱和共享文件夹互不牵连，是两个独立的 scope。

### 6.3 最终权限 = 账号角色 ∩ 共享权限

| 账号角色 | 共享权限 | 实际能做什么 |
| --- | --- | --- |
| 只读 | 可编辑 | **只能看**（账号级封顶） |
| 读写 / 管理员 | 只读 | 只能看 |
| 读写 / 管理员 | 可编辑 | 增、改、删、勾选完成 |

前端禁用按钮只是提前规避，**后端做最终校验**。完整角色说明见 [通用交互与登录 · 角色与权限](通用交互与登录.md#四角色与权限)。

## 七、被共享方在待办页看到什么

这一页只是"开权限"，实际协作发生在 [待办清单](待办清单.md)。对方登录后：

| 位置 | 表现 |
| --- | --- |
| 左侧文件夹树 | 共享来的文件夹带徽标 `共享自 <所有者>`，只读时是 `共享自 <所有者> · 只读`；节点样式与自己的不同 |
| 树节点操作 | **没有删除按钮**（文件夹结构只归所有者维护）；`+` 只剩 `新建待办`，不能建子文件夹；只读时连拖拽排序都关掉 |
| 任务卡片 | 带徽标 `共享 · <所有者>`（只读时加 ` · 只读`）；只读时勾选框、`编辑`、`删除` 全部禁用，title 分别是 `只读共享，无法编辑` / `只读共享，无法删除`，卡片不可拖动，分区内的批量操作入口隐藏 |
| 详情抽屉 | 多一行 `共享权限`：`只读` 或 `可编辑` |
| 标签 | 共享来的标签显示为 `<所有者> / 标签名`，与自己同名标签区分 |
| 新建/编辑弹窗 | 分类与标签选择器**按数据所有者过滤**：编辑谁的任务就只能选谁的文件夹/标签；收件箱那项会写成 `<所有者> 的收件箱（无分类）`；若对方还没有标签显示 `该数据所有者还没有标签。` |
| 移动任务 | 只能移到**同一所有者的可写文件夹**，防止把别人的任务挪成自己的 |

这套限制的原因是：**任务的归属由 `user_id` 决定，共享只改变"可见可写"，不改变归属**。跨所有者移动会让数据所有权变得含混，所以直接禁止。

## 八、接口的唯一性约束

`todo_shares` 表的约束决定了上面「重复共享等于更新权限」的行为：

- `scope` 只能是 `category` 或 `inbox`；
- `scope = 'category'` 时 `category_id` 必须有值，`scope = 'inbox'` 时必须为空；
- `UNIQUE(owner_id, grantee_id, scope, IFNULL(category_id, 0))` —— 同一对账号在同一范围上只会有一条记录。

接口定义与请求体见 [后端 API 说明](../后端API说明.md) 中的待办共享部分。

| 页面动作 | 接口 |
| --- | --- |
| 页签切换 / 刷新 | GET `/todo-shares?scope=mine\|received\|all` |
| 打开新建弹窗（取候选项） | GET `/todo-shares/options` |
| 创建共享 | POST `/todo-shares` |
| 改权限 | PATCH `/todo-shares/:id` |
| 取消共享 | DELETE `/todo-shares/:id` |

## 九、常见问题

**Q：为什么下拉里找不到某个同事？**
只列「已启用」的账号。对方多半还在[待审核](账号管理.md)，或被禁用了；也可能登录的就是这一个账号（不能共享给自己）。

**Q：我给了可编辑，对方还是改不了。**
先看对方的账号角色 —— `只读` 账号无论共享权限多高都只能看。另外确认你共享的是**包含该任务的那个文件夹**（或其祖先），或任务其实在收件箱里、需要单独共享收件箱。

**Q：共享之后能在对方那里新建子文件夹吗？**
不能。文件夹层级由所有者维护，被共享方只能在已有文件夹里增删任务。

**Q：取消共享会不会删掉对方看到的任务？**
不会，任务一直在你这里，只是对方失去可见性。

**Q：对方能不能反过来看到我的全部数据？**
不能。共享是逐条显式授权，没有"全部开放"这种范围。

**Q：`全部共享` 页签怎么不见了？**
它是管理员专属。普通账号需要审计所有授权关系时，请让管理员导出或代为查看。
