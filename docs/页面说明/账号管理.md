# 账号管理页面使用说明

> 页面地址：`/gitstatus/pages/account.html`
> 只有**管理员**能用这一页：审核注册申请、建号、改角色、禁用、迁移数据、删号。
> 通用部分（导航、登录、角色、页面桌宠）见 [通用交互与登录](通用交互与登录.md)。

![账号管理页面](../screenshots/账号管理.png)

---

## 一、谁能打开这一页

| 条件 | 页面表现 |
| --- | --- |
| 未登录 | 显示登录卡片（用户名 / 密码 / `登录`）；这里的 `登录` 按钮登录后回到 `index.html`（其他页面是跳待办页），见 [通用交互与登录 · 各页面的登录入口形态](通用交互与登录.md#31-各页面的登录入口形态) |
| 已登录但角色不是 `管理员` | 显示 `需要管理员权限`，正文「账号管理仅对管理员开放，请使用管理员账号登录。」，给两个出口：`返回 Git 洞察` / `前往待办页登录`。同时头像卡里的角色会明说：`当前账号「<用户名>」的角色是只读，账号管理仅对管理员开放。` |
| 管理员 | 完整功能 |

顶栏里的 `账号管理` 入口本身就是**管理员才渲染**，非管理员看不到链接，但手输 URL 也会被上面这道面板挡住。后端同样在 `/users` 系列接口上要求 admin 角色，直接调 API 会 403。

> 会话过期时这一页还会多提示一句：`请重新登录后再访问账号管理。`

## 二、页面骨架

```
页头：筛选区（搜索 + 角色 + 状态）+ 工具栏（刷新 / 新建用户）
用户列表卡片：标题 用户列表 · 统计 待审核 N · 共 M 个用户
表格：ID / 用户名 / 角色 / 状态 / 创建时间 / 最近登录 / 操作
分页条：第 X / Y 页  ◀ 上一页   下一页 ▶
```

| 控件 | 选项 | 行为 |
| --- | --- | --- |
| 搜索框 | 占位 `搜索用户名` | **输入即搜**（300 ms 防抖），后端是不区分大小写的模糊匹配 |
| 角色筛选 | `全部角色` / `管理员` / `读写` / `只读` | 切换后回到第 1 页重新拉取 |
| 状态筛选 | `全部状态` / `待审核` / `已启用` / `已禁用` | 同上 |
| `刷新` | — | 按当前筛选条件重查 |
| `新建用户` | — | 打开建号弹窗 |

统计条里的 `待审核 N` 是**全库**待审核数量（不受筛选影响），用来提醒管理员还有多少申请没处理。

每页固定 20 条，分页只有上一页/下一页，当前页显示为 `第 X / Y 页`；没有结果时表格区显示 `没有符合条件的用户`，加载中文案 `加载用户列表...`。

**排序规则**：默认把 `待审核` 的账号顶到最前面，其余按 ID 升序 —— 新申请一定在首屏。

## 三、审核注册申请

`只读` 之外的账号无法自己注册（只有[待办清单页](待办清单.md)有注册入口），新注册一律是 `待审核` + `只读`。**审核中的账号操作列只有两个按钮**：

| 按钮 | title | 确认文案 | 结果 |
| --- | --- | --- | --- |
| `通过` | 通过审核，允许该用户登录 | `通过用户「X」的注册申请？通过后该账号即可登录。` | `已通过审核，该账号现在可以登录`，状态变 `已启用`，角色保持 `只读` |
| `拒绝` | 拒绝注册并删除该用户数据 | `拒绝用户「X」的注册申请？拒绝后该用户数据会被删除，且无法登录。` | `已拒绝并删除该账号` —— 这是**真删**，账号连同数据一起消失 |

> 待审核账号此刻还没有任何数据，所以「拒绝 = 删除」是安全的。审核完成后这一行就会换成 `编辑` / `迁移` / `删除` 三个按钮。

新注册能被受理的上限是 **20 个待审核账号**（可由配置项 `maxPendingRegistrations` 或环境变量 `MAX_PENDING_REGISTRATIONS` 调整），超限时注册接口直接拒绝。

## 四、新建用户

弹窗标题 `新建用户`，副标题 `创建账号并分配角色`。

| 字段 | 规则 |
| --- | --- |
| 用户名 * | 占位 `3-32 个字符`；3–32 个字符，重名会被后端拒绝（`username already exists`） |
| 密码 * | 占位 `至少 6 个字符`，hint 同样是 `至少 6 个字符`；少于 6 位前端就拦下 |
| 角色 | `只读` / `读写` / `管理员`，默认 `只读`；**`管理员` 选项是禁用状态**，见[第六节](#六唯一管理员与自锁保护) |
| 状态 | `已启用` / `已禁用`，默认 `已启用` |

前端校验提示：`请输入用户名`、`新建用户的密码至少 6 个字符`、`系统仅有唯一管理员，不支持创建或转移管理员角色`。成功提示 `用户已创建`，失败提示 `保存失败（HTTP 状态码）`。

> 管理员手工建的号默认就是 `已启用`，不需要再走审核 —— 审核流程只针对自助注册。

## 五、编辑用户

同一个弹窗换用编辑态：标题 `编辑用户`，副标题 `用户 #<ID> · 密码留空表示不修改`。

| 字段 | 编辑时的行为 |
| --- | --- |
| 用户名 | 可以改（后端仍校验 3–32 与重名） |
| 密码 | **留空即不修改**，必填星号消失，hint 变 `留空则保持原密码不变`；要改则至少 6 位，否则提示 `新密码至少 6 个字符` |
| 角色 | 可改，但 `管理员` 选项依旧禁用 |
| 状态 | 在 `已启用` / `已禁用` 之间切换 |

**改自己时的额外限制**：角色与状态两个下拉直接置灰，hint 变成 `不能修改自己的角色与状态。` —— 防止管理员把自己降职后没人能改回来。编辑当前管理员账号（非自己）时 hint 是 `当前管理员账号。`

成功提示 `用户已更新`。

禁用一个账号的效果：该账号立刻无法登录，已发出的 Token 在下次请求校验时被拒（后端会检查状态），数据保留不动。

## 六、唯一管理员与自锁保护

系统按「**有且只有一个管理员**」设计，这是有意为之，避免多人互相改角色导致权限失控。落地方式从数据库到页面一层层收紧：

| 层 | 约束 |
| --- | --- |
| 数据库 | 部分唯一索引：`CREATE UNIQUE INDEX uq_users_single_admin ON users(role) WHERE role = 'admin'`。启动时若已检出多于一个管理员，会**跳过**建索引并写日志告警，避免老库启动失败 |
| 注册 | 第一个注册成功的用户自动成为 `admin` + `已启用`；此后所有自助注册一律 `readonly` + `pending` |
| 建号接口 | 请求角色为 `admin` → 400 `administrator role cannot be created` |
| 改号接口 | 把别人改成 `admin` → 400 `administrator role cannot be transferred`；把管理员改成非 `admin` 或改成非 `active` → 400 `cannot demote or disable the last active admin`；`admin` 的状态不是 `active` → 400 `administrator must be active` |
| 删除接口 | 删除当前登录账号 → 400 `cannot delete your own account`；删除最后一个可用管理员 → 400 `cannot delete the last active admin` |
| 页面 | 角色下拉里的 `管理员` 永远禁用，hint 固定为 `系统仅有唯一管理员，不支持创建或转移管理员角色。`；自己的行不能改角色/状态；自己的 `删除` 按钮禁用（title `不能删除当前登录账号`） |

因此：

- **页面上无法把管理员交给别人，也无法自杀**（既不能删自己，也不能把自己降级/禁用）。
- 确实要换管理员，只能**直接改数据库**：停后端 → 把 `users` 表中原管理员的 `role` 改掉、目标账号改成 `admin` 且 `status='active'`（同一时间只能留一行 `admin`）→ 重启。改完原管理员就退成普通账号，新管理员登录即可。
- 唯一管理员被禁用/删除的路径都被封死，所以不必担心"没人能审核注册"的死角。

> 页面 HTML 里还留着一句旧提示「系统有且只有一个管理员；如需更换，请编辑目标用户并选择"管理员"。」，脚本打开弹窗时会把它**覆盖**成上面那句准确表述 —— 以实际看到的文案为准。

## 七、迁移用户数据

操作列的 `迁移`（title：「把该用户的待办数据迁移给其他用户」）打开 `迁移用户数据` 弹窗，副标题「把源用户的分类、标签、待办和图片迁移给另一个用户」。

- `源用户` 只读展示（就是从哪一行点进来的）。
- `目标用户` 是下拉，候选是**其他所有用户**；系统里没别人时显示 `没有可用的目标用户`，没选就提交提示 `请选择目标用户`。
- 字段下方 hint 原文（这句话就是迁移语义的摘要）：

  > 会迁移源用户的分类、标签、待办和图片；源用户的这些数据将被清空，目标用户已有的同名分类/标签会自动合并。

- 确认框正文：`确定将「A」的全部待办数据迁移给「B」？迁移后源用户的分类、标签、待办和图片会被清空。`
- 成功提示带明细：`迁移完成：12 个待办、4 个分类、3 个标签、5 个附件`；失败 `迁移失败（HTTP 状态码）`。

### 7.1 具体做了什么

| 对象 | 处理方式 |
| --- | --- |
| 分类（文件夹） | **按层级重建**到目标账号下：逐层比对，**同名同父级**的分类直接复用目标已有的那一个，否则新建；源用户的原分类随后清空 |
| 标签 | **同名合并**（不分大小写地按名称匹配），重复的关联关系会被清理掉，不会产生两个一样的标签 |
| 待办 | 只把归属字段从源用户改成目标用户，**任务 ID 不变**，因此链接、历史引用继续有效 |
| 附件记录 | 与待办同样只改归属；磁盘上的图片/文件在**事务提交成功后**从源用户目录搬到目标用户目录 |
| 提醒 | 提醒表按任务 ID 存储、不带用户字段，因此**跟着任务一起过去**，无需也不应单独迁移 |
| 共享记录 | 不迁移。迁移完成后源用户已无数据，针对它的授权自然失效，需要的话由目标用户重新共享 |

整个过程在一个数据库事务里完成，中途出错会整体回滚；只有事务成功后才 move 磁盘文件。

### 7.2 什么时候用

- 同事离职/换号：把他的任务并到你或接手人的账号，再删掉空壳账号。
- 测试账号转正：把试用账号里积累的数据搬到正式账号。

> **迁移不可撤销**，源用户侧会被清空。执行前建议先用 `刷新` 看一眼对方的量级，或备份数据库文件。

## 八、删除用户

操作列 `删除`（自己的行禁用）。确认框正文：`确定删除用户「X」？其待办数据会一并删除。` 成功提示 `用户已删除`。

删除是**物理删除且连带全部数据**：

| 被删掉的东西 | 说明 |
| --- | --- |
| 账号本身 | 用户名、密码散列、角色、状态 |
| 待办、分类、标签、完成记录、提醒 | 外键级联删除 |
| 附件 | 数据库记录级联删除，**磁盘上的图片/文件目录另行清理** |
| 桌宠素材 | 该用户上传的自定义宠物形象文件一并清理 |
| 别人共享给他的记录 | 失去接收方，不再有意义 |

想保留数据请先做[迁移](#七迁移用户数据)，再删号。删除最后一个可用管理员会被拒绝（见[第六节](#六唯一管理员与自锁保护)）。

## 九、接口对应

| 页面动作 | 接口 |
| --- | --- |
| 列表 / 搜索 / 筛选 / 分页 | GET `/users` |
| 单个账号详情 | GET `/users/:id` |
| 新建用户 | POST `/users` |
| 编辑（改名/改密/角色/状态） | PATCH `/users/:id` |
| 通过审核 | PATCH `/users/:id`（把 `status` 置为 `active`） |
| 拒绝注册 | DELETE `/users/:id` |
| 数据迁移 | POST `/users/:id/transfer` |
| 删除用户 | DELETE `/users/:id` |

参数表与响应示例见 [后端 API 说明](../后端API说明.md) 的用户管理章节。

## 十、常见问题

**Q：新注册的人一直登不进去，提示「账号正在等待管理员审核，暂时无法登录」。**
正常，等你在列表首屏点 `通过`。首屏没有就先 `刷新`，或看统计条的 `待审核` 数字。

**Q：角色下拉里的「管理员」为什么是灰的？**
系统只允许一个管理员，且不支持在页面上创建或转移，见[第六节](#六唯一管理员与自锁保护)。

**Q：我想改自己的密码，但角色/状态是灰的。**
改密码没问题 —— 只有**角色与状态**不能自己动（防止自锁）。密码留空表示不改，填了就必须 ≥6 位。

**Q：能不能把某个人的任务只挪一部分给我？**
不能，迁移是整账号打包。要部分转移请在[待办清单](待办清单.md)里用文件夹筛选后手动处理，或先共享再各自整理。

**Q：迁移后对方的登录密码/角色会变吗？**
不会，迁移只动待办相关数据，账号属性原样保留。

**Q：删掉的用户能恢复吗？**
不能，磁盘文件也会一起清掉。请把它当成不可逆操作。

**Q：待审核账号占名额吗？**
占。待审核总数达到上限（默认 20）后新的注册会被拒绝，及时处理积压申请即可。
